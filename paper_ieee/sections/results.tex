Table~\ref{tab:rq1} gives the oracle gap on both held-out sets. On held-out
set~1 (\RQoneDocuments{} documents, \RQoneQuestions{} questions), the best
single setup is \RQoneBest{}, with hybrid Recall@1,250 of \RQoneBestRecall{},

The cross-fitted oracle reaches \RQoneOracle{}, a gap of \RQonePrimaryGap{}

pre-registered rule gives \RQoneDecision{}. An oracle that picks and scores on

(\RQoneHTwoDropRuleDocuments{} documents, \RQoneHTwoDropRuleQuestions{}

(\RQoneHTwoDropRuleBestRecall{}), the oracle reaches
\RQoneHTwoDropRuleOracle{}, and the gap is \RQoneHTwoDropRuleGap{}
\RQoneHTwoDropRuleGapCI{}. The sensitivity gold gives
\RQoneHTwoSensitivityGap{} \RQoneHTwoSensitivityGapCI{}, an interval entirely

\RQoneHTwoCertainOnlyGap{} \RQoneHTwoCertainOnlyGapCI{}. All three are

A pre-stated check removes the \RQoneHRCheckExcludedQuestions{} questions on

and \RQoneHRCheckWithGap{} \RQoneHRCheckWithGapCI{} with them; the second
figure differs slightly from the main gap above only because the check draws
its own bootstrap. Both are NO-GO.

The setup chosen on tuning data, applied unchanged, is statistically tied
with the best single setup on every held-out set and gold variant. On
held-out set~2 it ranks \RQoneHTwoDropRuleTuningWinnerRank{} of
\RQoneSetups{} (\RQoneHTwoDropRuleTuningWinnerRecall{}).
The setup chosen on tuning data, \RQoneTuningWinner{}, applied unchanged, is
statistically tied with the best single setup on every held-out set and gold
variant. On held-out set~1 it ranks only \RQoneTuningWinnerRank{} of
\RQoneSetups{} by mean, but within a large group of tied setups; on held-out
set~2 it ranks \RQoneHTwoDropRuleTuningWinnerRank{}
(\RQoneHTwoDropRuleTuningWinnerRecall{}).
Pooled over both sets (\RQonePooledDocuments{} documents,
\RQonePooledQuestions{} questions; secondary), the oracle
(\RQonePooledOracle{}) stays below the tuning winner
(\RQonePooledTuningWinnerRecall{}), a gap of \RQonePooledGap{}
\RQonePooledGapCI{}. Pooling does not narrow the interval, so the bound comes
from the replication, not from pooling.

Selecting a chunking setup per document therefore does not improve retrieval
over a single small-chunk setup under a fixed token budget.

At a fixed token budget, smaller chunks retrieve more of the gold text. On
tuning data, Spearman's $\rho$ between measured chunk size and recall is
negative for every parser and budget (Fig.~\ref{fig:rq2}), ranging from \RQtwoRhoRange{}, so RQ2
holds as pre-registered. The best setups have measured chunk sizes of
\RQtwoBestSizes{} tokens. The OHR-Bench documents of held-out set~1 show the
same pattern ($\rho$ from \RQtwoHeldOutOHRRhoRange{}, best sizes
\RQtwoHeldOutOHRBestSizes{} tokens).

Held-out set~2 confirms it (Table~\ref{tab:rq2h2}). All
\RQtwoHTwoNegative{} of the \RQtwoHTwoValues{} values of $\rho$ (three gold
variants, two parsers and three budgets, each over
\RQtwoHTwoSetupsPerParser{} setups per parser) are negative. The effect is
weakest at the largest budget: at 2,000 tokens,
\RQtwoHTwoLargestBudgetIncludeZero{} of the
\RQtwoHTwoLargestBudgetValues{} intervals include zero.
